# Peer Review — Лабораторна робота №8

## 1. Мета перевірки

Метою взаємного рецензування є перевірка якості
рефакторингу системи медичної клініки, правильності
застосування GRASP та відповідності архітектури
вимогам лабораторної роботи.

## 2. Перевірка структури проєкту

Під час перевірки було розглянуто такі компоненти:

- domain — доменні сутності та бізнес-логіка;
- application — координація сценаріїв використання;
- infrastructure — репозиторії, SMS та генерація квитанцій;
- presentation — консольний інтерфейс.

Висновок: відповідальності розподілені між окремими
шарами системи.

## 3. Перевірка GRASP-патернів

| Патерн | Результат перевірки |
|---|---|
| Information Expert | Бізнес-логіка розміщена в доменних сутностях |
| Creator | Використовується Appointment.create() |
| Controller | AppointmentController координує запити |
| Low Coupling | Використовуються інтерфейси та DI |
| High Cohesion | Класи мають окремі відповідальності |
| Pure Fabrication | Створені технічні класи |
| Indirection | Використовуються інтерфейси |
| Polymorphism | Використовується ConsultationPricing |
| Protected Variations | Нестабільні алгоритми ізольовані інтерфейсами |

## 4. Виявлені переваги

1. Покращено інкапсуляцію доменних сутностей.
2. Бізнес-логіку перенесено з монолітного сервісу.
3. Реалізовано окремі стратегії ціноутворення.
4. Відокремлено консольний інтерфейс від інфраструктури.
5. Створено окремі інтерфейси для технічних операцій.
6. Покращено можливість тестування та розширення системи.

## 5. Рекомендації

1. Додати автоматизовані модульні тести.
2. Передбачити обробку некоректного введення користувача.
3. У майбутньому замінити демонстраційне сховище
   InMemoryAppointmentRepository на постійну базу даних.
4. Перевірити метрики CBO та LCOM4 після остаточних змін.
5. Удосконалити консольний інтерфейс.

## 6. Загальний висновок

За результатами Peer Review встановлено, що рефакторинг
покращив архітектуру системи медичної клініки.

Застосування GRASP дозволило розділити відповідальності,
зменшити залежності між компонентами та перенести
бізнес-логіку до відповідних доменних об'єктів.

Проєкт компілюється та демонструє основний сценарій
запису пацієнта на прийом із розрахунком вартості
консультації, лабораторних аналізів і страхового покриття
